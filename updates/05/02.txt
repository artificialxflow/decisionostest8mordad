خلاصه وضعیت
تصویری که آماده کردیم، در واقع نمونه‌ی «Control Center / Dashboard داخلی کاربر» است، نه صفحه‌ای که هر بازدیدکننده قبل از ورود ببیند.
معماری حرفه‌ای DecisionOS باید دو سطح کاملاً جدا داشته باشد:
۱. صفحه عمومی — قبل از ورود
هر شخصی که وارد دامنه DecisionOS می‌شود، این صفحه را می‌بیند:
DECISIONOS
                         │
        ┌────────────────┼────────────────┐
        ↓                ↓                ↓
      معرفی           خدمات            متخصصان
        │                │                │
        └────────────────┼────────────────┘
                         ↓
                  ثبت‌نام / ورود
                         │
              ┌──────────┴──────────┐
              ↓                     ↓
          مشتری/کاربر             متخصص
              │                     │
              ↓                     ↓
       Customer Dashboard      Expert Dashboard
در این صفحه هیچ اطلاعات خصوصی، پرونده، سند، آمار یا اطلاعات مشتریان نمایش داده نمی‌شود.

۲. صفحه کاربری مشتری
بعد از Login، کاربر وارد Dashboard اختصاصی خودش می‌شود.
همان تصویری که الان طراحی کردیم، باید با داده‌های واقعی همان کاربر نمایش داده شود:
Login
  ↓
تشخیص Tenant
  ↓
تشخیص User
  ↓
تشخیص Role
  ↓
Permission Check
  ↓
Customer Dashboard
مثلاً مشتری فقط موارد مجاز خودش را می‌بیند:
┌─────────────────────────────┐
│ DecisionOS                  │
├─────────────────────────────┤
│ خانه                        │
│ پرونده‌های من               │
│ اسناد من                    │
│ مشاوران / متخصصان           │
│ درخواست مشاوره              │
│ جلسات من                    │
│ اعلان‌ها                    │
│ تنظیمات                     │
└─────────────────────────────┘

۳. متخصص Dashboard متفاوت دارد
اگر شخص با Role = Expert وارد شود، همان Dashboard مشتری نباید نمایش داده شود.
مثلاً:
Expert Login
     ↓
Expert Dashboard
     │
     ├── پرونده‌های ارجاع‌شده
     ├── درخواست‌های مشاوره
     ├── جلسات
     ├── وظایف
     ├── امتیاز و Reputation
     ├── درآمد
     └── پروفایل تخصصی

۴. مدیر سیستم
Admin/Manager نیز Dashboard مخصوص خود را دارد:
Admin Login
     ↓
Admin Control Center
     │
     ├── Users
     ├── Experts
     ├── Tenants
     ├── Workspaces
     ├── Cases
     ├── Documents
     ├── Permissions
     ├── Audit Log
     ├── System Events
     └── Reports
بنابراین تصویر فعلی را نباید به‌عنوان صفحه عمومی سایت به برنامه‌نویس بدهیم.

نتیجه
پس پاسخ دقیق:
هرکس وارد سایت شود: صفحه عمومی DecisionOS را می‌بیند.
مشتری پس از ورود: Dashboard اختصاصی خودش را می‌بیند.
متخصص پس از ورود: Dashboard تخصصی خودش را می‌بیند.
Admin/Manager: Control Center مدیریتی خودش را می‌بیند.
هیچ کاربری نباید اطلاعات کاربر، پرونده، اسناد یا آمار سایر کاربران را ببیند.
این تفکیک باید از Sprint 2 در Backend و Frontend با RBAC + Multi-Tenant + Permission Enforcement پیاده‌سازی شود؛ صرفاً مخفی‌کردن منو در Frontend کافی نیست.
